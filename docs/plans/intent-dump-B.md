# 二层（巢穴）9 个 Boss 的意图数据（权威抽取）

> 用途：喂给 `docs/plans/intent-table-audit.md` 里那张 `Boss意图表.xlsx` 的 **2层1号 / 2层2号 / 2层3号** 三张工作表。
> 全部数据从**代码**里抽，不猜：
> · 剧本 = `src/Hooks/Core/*Script.cs`（`BossTurn` / `ScriptCard` 语义见 `BossScript.cs`、规划见 `BossScriptPlanner.cs`）；
> · 特殊效果正文 = `content/localization/zhs/monsters.json`（key 见 `BossDefs.SpecialLocByAct` / 变体 `SpecialLoc`）；
> · 进阶 = `BossDefs.AscensionUpgradesByAct` / `AscensionRelicsByAct` 的 Act=2 行 + 变体自己的 `AscensionUpgrades` / `AscensionRelics`；
> · 收藏家掉落 = `Core/DownfallCollectibleCompat.cs` 的 `LootTable` + `ResolveLoot` 的遭遇/变体 switch。
>
> **编号口径**：「N 号」= `Core/BossKeys.cs` 的**同角色内部编号**（猎 / 机 / 骨 / 储 / 战 各自排号），
> 不是同层全局序号（`BossKeys.RosterFor(1)` 的 1～9）。所以本层同时存在三只「2层1号」（物理机 / 灵魂骨 / 铸剑储君）。
>
> **能量口径**：剧本里 `BossTurn.Energy > 0` 时**整个覆盖**本回合能量（`CharBossMonster.Turn.cs`：`energy = scriptedTurn.Energy`，不叠加遗物），
> `ForceZeroEnergy` 则强制 0。下表括号里的「N费」就是这个覆盖值。
>
> **血量口径**：`BossDefinition.HpForAct` + `NeowBlessing`（拾起 +120、每进一幕 +180 ⇒ 第二幕 +300）。见 `CharBossMonster.Descriptor.cs`。

**「仆从不足 2 个才召唤」在剧本/代码里怎么体现（三层）**

1. **判定（真正生效的地方）**：`MinionSummonPatch.TrySummon` 是 `MinionStrike` / `MinionDiveBomb` / `MinionSacrifice` 三张牌 `OnPlay` 的 **Harmony 前缀**。
   命中条件三条：① 牌的 owner 是 `CharBossMonster`；② 她身上有 `BossCallToArmsPower`（＝这一场真的是仆从储，真人玩家打这三张牌完全不受影响）；
   ③ `BossMinionMonster.CountAlive(boss) < BossCallToArmsPower.MinionCap`（= 2）。
   三条都成立 ⇒ **拦掉原版 `OnPlay` 并改为召唤**（`CreatureCmd.Add<对应仆从>` → 记 `Summoner` → 登记进 `Registry` → 挂 `MinionPower` → `RefreshPlannedIntents`）；
   任何一条不成立 ⇒ 返回 `true` 放行原版效果。

2. **剧本侧只写牌、不写「召唤」**：剧本里照常写 `MinionStrike` / `MinionDiveBomb` / `MinionSacrifice` 这三张（`RegentMinionScript.Build`），
   **不区分**这一手是召唤还是原版效果 —— 由上面那条前缀在**打出那一刻**按当时的存活数决定。

3. **意图侧要提前算**：意图是在**玩家回合**就规划好的，那时「这一回合会召唤几只」还不知道，
   所以 `BossScriptPlanner.IsMinionSummonHere` 从「场上现有存活数」起算、按剧本顺序每遇到一张仆从牌就 `planned++`，
   到 `planned >= MinionCap` 之后的仆从牌才算「原版效果」⇒ 意图里第 1/3 回合的提示才是对的（召唤 vs 13 伤 / 7 格挡）。
   同样地，`MinionSacrifice` 的格挡要按「这张是原版效果」才画得出来。

## 数值与常见说法不一致 / 可能过时的点

1. **编号有两套，别混用**：`BossKeys` 的「N 号」是**同角色内部**编号（本层因此有三只「2层1号」），
   而 `BossKeys.RosterFor(1)` 给的是同层全局序号（涂毒猎1 … 杂耍战9，物理机排第 3、仆从储排第 7）。
   Excel 工作表按「层号 + 同角色编号」分（2层2号 = 蛇眼猎/杂耍战/王储；2层3号 = 仆从储），与全局序号**不一致**。
2. **涂毒猎血量**：`docs/plans/boss-silent-poisoner.md` §1 写「`Hp[1] = 185` + 涅奥 150×2 = **485 血**」——
   这是双份过时（`Hp` 数组现在全 70；涅奥现在是「拾起 +120、每进一幕 +180」）⇒ 实际 **370**。
3. **何人僭越扣多少铸造**：`RegentScript.cs` 文件头注释写「失去 **3** 点铸造」（方法注释 `LoseForge` 也还留着一句「−3」），
   而代码常量 `KnowThyPlacePower.ForgeLoss = 5`、本地化文案也是 **5**。
4. **放血战的特殊效果是「死亡收割」不是「扯碎」**：`BleedIroncladScript.cs` 文件头仍写着 2026-10-27 的「扯碎（单次 ≤5 点生命也触发撕裂）」，
   实际 `SpecialPowerByAct[1] = BossRendingPower` + 本地化 `IRONCLAD_BOSS.rending` = **造成未格挡伤害 → 等量回血**（2026-10-28 改稿）。
   同一处 `TierBossEncounters.cs` 里 `IroncladBloodBossEncounter` 的注释也仍写「他还没有专属剧本，走贪心 AI，没有特殊效果」—— 全部过时。
   另外 `docs/plans/boss-ironclad-bleed.md` §0（自称「以这一节为准」）的第 4 / 7 回合仍写「**御血术**」，
   代码已按 2026-10-28 削弱换成「**铁斩波**」（`BleedIroncladScript` 卡组注释也写了「替换御血术」）。
5. **杂耍战的数值是削弱后的版本，设计文档没跟上**：`docs/plans/boss-juggler.md` §1/§4 仍是削弱前剧本
   （第 2 回合打击×3、第 3 回合预备打击 + 踩踏、第 4 回合打击/防御/痛击、遗物「奥利哈钢」、进阶 8 坚毅 / 进阶 9 预备打击+）；
   代码（v0.2.321 后）是：预备打击/踩踏 → **突破 / 邪眼**，奥利哈钢 → **精致折扇**，进阶 8 = 无惧疼痛+邪眼，进阶 9 = 完美打击+彼岸咆哮。
6. **铸剑储君能量少了 1 点**：`docs/plans/handover-regent-boss.LATEST.md` §4 写「2,2,2,2,**4**,2,2,2,3」，
   代码现在是「2,2,2,2,**3**,2,2,2,3」（第 5 回合 = 基础 2 + 上一回合「汇流」+1）。
7. **物理机「冰寒」的生成数量说法不一致**：`ClawDefectScript.cs` 文件头写「= 玩家方单位总数（真人玩家 + 她们召唤物），但不算佩尔士兵/异鸟宝宝/崩坠史莱姆」，
   而 `docs/plans/boss-defect-claw.md` §3.1 记的是用户 2026-10-24 订正后的「**只检测真人玩家数**」（宠物/召唤物不算）；
   代码里其实是原版行为（`HittableEnemies` 已被收窄成真人玩家），那句「排除清单」注释是废弃写法。
8. **三种仆从的血量比设计原文低很多（待确认）**：`MinionMonsters.cs` 头部照抄的设计数字是 **36/40、23/26、30/33**，
   代码实际是 **22/25、12/14、15/17**（伤害/格挡仍是 6/9、13/16、7/10，与设计一致）。
   另外设计原话「俯冲仆从：造成 13 点伤害，**使自身死亡**」在 2026-11-05 被改成「**复读**同一意图、不自爆」，注释里记了改口但设计段落没删。
   → 待确认（是有意削弱后忘了改注释，还是漏改数值）。
9. **仆从储第 9 回合那张牌名不一致**：`RegentMinionScript` 该回合的 `Note` 写「究极**打击**」，而实际造进手牌的是 `UltimateDefend`（**究极防御**，1 费 11 格挡；`Jackpot` 大奖 3 费才是没费那张）。按代码为准。
10. **王储的特殊效果换了整版**：`docs/plans/boss-king-regent.md` §1/§4 记的是旧版「名字带『王』的牌 → 玩家本回合失去 1 力量 / 攻击被完全格挡 → 玩家本回合 +1 力量」，
    代码 + 本地化现在是 2026-11-02 改稿的「**返顶 → 所有玩家得 1 层麻痹（下一张攻击牌伤害 −50%）**」。
11. **「带毒刺击」的文案比实现宽松**：本地化只写「每当对敌方造成未被格挡的伤害时，就将自身的一点中毒转移给目标」，
    实现里还多两条限制：**只对「有牌来源」的伤害生效**（`cardSource == null` 直接返回 ⇒ 荆棘反伤、中毒跳伤都不转移），
    且**双向**（她打玩家也能把毒转给玩家）。文案没体现这两条。
12. **灵魂骨第 1 回合「挽歌」的 X 到底是几**：`SoulBoneScript.cs` 的能量注释把第 1 回合记成「拖延+(2) + **自动化+(1)** + 挽歌(0) = 3」，
    但「自动化+」升级后是 **0 费**（反编译 `Automation.OnUpgrade → EnergyCost.UpgradeBy(-1)`）⇒ 实际 拖延+(2) + 自动化+(0) = 2，
    **挽歌 X = 1**（`docs/plans/boss-soul-bone.md` 里「逐回合能量」那一条记的也是「挽歌以 1 费打出」）。剧本代码注释是过时的那一份。
13. **一层那张旧表**：`docs/plans/intent-table-audit.md` §二 已指出 Excel「指令 · 血量」第一幕按 +150 算错（应 +120）；
    二层那行 370/366/375/380/375 与本文件一致 ✅，但同一张表里 **铸剑储君「何人僭越」写成「失去 25×玩家人数」** 仍是过时口径（恒为 25）。
