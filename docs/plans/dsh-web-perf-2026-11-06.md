# DSH Web 界面卡顿诊断（2026-11-06）

> 起因：用户反馈「浏览器 dsh 界面很卡」。以下是本机实测数据 + 结论 + 已约定的应对方式。

## 一、实测数据

### 前端

`node_modules\@deepseek-ai\dsh-web-frontend\dist\assets\`：`index-*.js` 0.38 MB + `vendor-*.js` 0.71 MB。
搜 `tanstack` / `Virtualizer` / `virtualize` **均无命中** ⇒ **时间线没有虚拟滚动**（整条线程全部留在 DOM）。

## 二、结论（按影响排序）

1. **前端把整条时间线挂在 DOM 里**（无虚拟滚动）：2,088 条回复 + 2,130 张工具卡片 + 大量代码块常驻。
2. **聊天里贴大表格/长日志是最贵的形态**：6 列 × 20+ 行的 Markdown 表格布局成本远高于纯文本；
   流式输出时前端每来一段增量就要重新解析 + 重排当前这条消息，消息越长越接近平方级。
3. **流式事件量巨大**：chunk 类记录合计 ≈5.6 万条（思考 2.5 万 / 工具调用流 1.7 万 / 回复流 1.5 万），
   每段都可能触发一次重渲染。
4. 服务端 1.7 GB 堆（峰值 3.4 GB）⇒ GC 停顿会让流式偶发一顿；但空闲 CPU 仅 1%，**不是它导致持续卡**。

## 三、应对（已与用户约定）

1. **本项目以后的回复形态**：大段内容（表格、清单、日志原文、代码摘录）**一律写进工作区文件**，
   聊天里只回 3~5 行要点 + 文件路径。已记进 `.dshwolf/cerebrum.md`。
2. 会话过大时**开新会话**；所有结论都落在文件里（`docs/plans/`、`AGENTS.md`、`.dshwolf/`），新会话可接续。
3. 页面卡到不能忍时 F5 刷新（丢掉累积 DOM；首屏会重放 7 万条事件，慢一下）。
4. 需要回收 1.7 GB 堆时可重启 dsh 服务（历史是持久化的，不会丢；会中断当前连接）。
5. 浏览器侧：`Shift+Esc`（Chrome 任务管理器）看该标签页内存，关掉无关标签/扩展。
