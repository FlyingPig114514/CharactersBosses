# 2026-10-20 补丁记录：奥斯提（Osty）「复活后朝右 / 没血条 / 每回合右边多一只手 / 不加血」

> 这一整串症状的**唯一根因**是：`src/Hooks/Core/BossOsty.cs` 的 `DropDeadPets()` 里
> **`pets.RemoveAt(i);` 这一行被吞进了上一行注释里**（源文件曾被 PowerShell 写入破坏成乱码，
> 修复时按 `?` 断行把这条语句留在了 `DetachFromCombat(pet);` 的注释尾部）。
> 于是：死掉的奥斯提**永远留在 `PlayerCombatState._pets`** → `GetPet<Osty>()` 永远返回**尸体**
> → `shadow.Osty` / `IsOstyAlive` 全错 → 每回合都判成「没有奥斯提」→ 再召一只。

已修（`3F9B5BB9`，用户实机确认「目前对了」）：

1. **`pets.RemoveAt(i);` 恢复成独立语句** —— 死宠物真的会被清掉了。
2. **`BossOsty.EnforceVisuals(boss)`（每帧）** —— 复活出来的是原版新建的节点，之后原版会
   ① 把 `Body.Scale` 写成正数（看着又朝右）；② 把「非本地玩家随从」的状态显示容器整块压掉。
   所以朝向与血条/状态栏必须**每帧确认**（`MirrorBody` + `ForceVisible`），只在摆位时做一次不够。
   挂载点：`Patches/BossFrameTickPatch.cs`（每帧驱动）。
3. **站位纠正改成两侧都跑** —— 以前只在玩家回合纠正，于是复活后整个她的回合都挂在右边，
   快结束时才瞬移到左边（用户实测）。现在判定「只要跑到 Boss 右手边就拉回来」，自己出手时的
   攻击位移不会被插手。
4. **爪牙（`MinionPower`）每帧兜底** —— 复活出来的生物不在我们 `MarkMinion` 的调用路径上，
   每帧确认一次；用 `_minionRequested` 记住"每只生物只请求一次"，避免叠层。
5. **`SafeOsty` 先在影子玩家的 `Pets` 里找活的奥斯提**，再退回 `shadow.Osty`；
   `IsHerLiveOsty` 的归属判定改为「`PetOwner == shadow` **或** 在影子玩家的 Pets 名单里」，
   不再强制 `entity.Side == boss.Creature.Side`（原版把宠物挂在 Allies 里，那条判断永远不成立）。
6. **不要自己乱召**：反编译 `OstyCmd.Summon` 的语义是
   「`summoner.IsOstyAlive`（读 Pets）→ `GainMaxHp(+amount)` 加血；否则复活旧的 / `PlayerCmd.AddPet<Osty>` 造新的」。
   所以「召唤 1 = 每回合加 1 点最大生命」这件事，**只有在 Pets 里那只是活的时才会发生** ——
   这又指回根因 1。缺奥斯提时我们只在她回合补召一次（`Update` 的 `osty == null` 分支）。

## 留下的诊断（可随时删）

`BossOsty.Update` 每回合打一行 `明细=fieldCount=… [OSTY hp=…/… alive=… owner=… side=…]`，
用来一眼看出 Pets 里躺的是不是尸体。确认稳定后可以删掉 `DumpPets` 与那半行日志。

## 教训（血的）

- **改 C# 源码只用 `read` / `edit` / `write` 工具。** 这个项目没有 git，
  用 PowerShell 的 `Get-Content`(PS5.1 默认 ANSI)+`Set-Content` 做替换会把整份文件变成乱码，
  而且**吞换行时会把下一行代码并进注释**，编译不报错但逻辑静默失效（本次就是）。
- 若已经踩了：先反向转码（UTF-8 → codepage 936 → UTF-8）把正文找回来，再逐个
  ① 用「行末出现 `\w+\.\w+\(…\);`」扫注释里被吞的语句；② 用同版本 DLL 反编译出的字符串字面量
  回填日志文案；③ 编译后核对「方法集合」和 `Logger.Log(` 次数与 DLL 是否一致。
