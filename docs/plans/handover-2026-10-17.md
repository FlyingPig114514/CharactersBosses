## 3. 关键机制与"必须记住的坑"

### 3.1 影子 Player（整个 mod 的地基）
- 怪物 `Creature` 上反射绑定 `<Player>k__BackingField` 与 `<Creature>k__BackingField`；
  `Creature.get_IsPlayer` 被强制 false（`CharbossIsolationPatches`），否则它会被当成玩家。
- 影子 Player **不在** `CombatState.Players` 里 → 原版永远不会替它触发钩子，所以必须手动补：
  - 战斗开始：`BossHookBridge.FireCombatStart`（遗物 `BeforeSideTurnStart`/`AfterSideTurnStart`）；
  - 每回合：`BossHookBridge.FireTurnStart`（`Hook.AfterPlayerTurnStart`）。
- 手动触发时**必须**把 `PlayerCombatState.TurnNumber` 临时掰回 1（反射写后备字段），
  否则遗物里 `TurnNumber <= 1` 的「本场第一次」条件不成立（裂核不出球就是它）；
  但**之后要恢复**，并且逐回合递增，否则红面具会每回合给虚弱。
- `BossRunStats.Ensure`：影子 Player 没有本层统计条目时，玩家打它的伤害结算会抛
  `Player with ID … not found in player stats`，整次 PlayCardAction 中断 → **牌卡在半空**。

### 3.2 出牌
- `CardCmd.AutoPlay(ctx, card, target, AutoPlayType.Default)`：**不扣能量/星星**，必须自己 `LoseEnergy`/`LoseStars`。
- 需要玩家选择的牌（抽3弃1 等）必须 `BossCardSelector.Push()` 顶上选择器，否则整回合挂死。
- 能量预算由我们算：`定义值 + (影子 pc.MaxEnergy − 角色基础能量) + 等离子球 + 充电`。
  其中 `pcs.MaxEnergy` 会走 `Hook.ModifyMaxEnergy`（**第三方 mod 的雷区**，见 §5）。

### 3.3 伤害/命中数预测
- 伤害：`vars.ClearPreview()` → `card.UpdateDynamicVarPreview(CardPreviewMode.Normal, target, vars)` → 读 **`PreviewValue`**
  （它已经过 `Hook.ModifyDamage`，**不要**再过一次 → 否则翻倍）。
- 命中数：多数在**计算变量** `CalculatedHits` 里（弹幕齐射=球数、终结技=本回合攻击牌数、散射炮=消耗状态牌数、
  螺旋钻机=打出的牌数），先走预览读它，再回退 `Repeat`（排除表）与写死例外表。
  早先只读 `Repeat` → 弹幕齐射显示成单段（用户报过）。

### 3.4 侧向语义
`CombatState.HittableEnemies` 原版永远是「敌方阵营」，Boss 用玩家卡打人时会打到自己
（弹跳药瓶自毒、下砸自减力量…）。`CombatSidePatches` 在敌方回合把它解释成玩家侧；
手动触发遗物钩子期间用 `HittableEnemiesSidePatch.ForceRelativeSide` 强制同样行为。

### 4.3 球位：当前唯一真正卡住的地方（重要）
```
现状：BossOrbDisplay.Attach 只做三件事
  1) NOrbManager.Create(creature, isLocal:true) 并反射写 <OrbManager> 字段
  2) 每帧 Follow() 只改 manager.Position（摆到立绘头顶）
  3) 手动往队列塞球后调 manager.AddOrbAnim()
但是：槽位仍然看不见、球也不出现。
```
**已排除的原因**（都有日志/代码依据）：
- 不是数量问题：`OrbQueue.Capacity = 3`、`Orbs.Count = 1`；
- 不是 `IsLocal`：球是用 `isLocal:true` 建的；
- 不是节点没挂上：日志有 `球位：已挂上原版 NOrbManager`。

**怀疑方向（下一个会话从这里查）**：
- `NOrbManager._Ready()` 里 `_orbContainer = GetNode("%Orbs")`；如果场景节点没进树/被我们的父级隐藏，槽位就不会显示。
  可以用 `manager.IsInsideTree()`、`manager.Visible`、`manager.GetNode("%Orbs").GetChildCount()` 逐一打日志验证；
- 原版槽位是由 `OnCombatSetup`（`CombatManager.CombatSetUp` 事件）调 `AddSlotAnim` 建的；
  **我们挂 manager 的时机在 `AfterAddedToRoom`，可能晚于 CombatSetUp** → 没人给它建槽位 →
  需要自己显式 `manager.AddSlotAnim(capacity)`，或监听事件补一次；
- `NCreature.SetOrbManagerPosition` 用的是 `Visuals.OrbPosition` 标记，我们改 Position 后可能被它覆盖；
- 注意 `NCreature._Process`/缩放回调会重设 Position，所以"每帧 Follow"是必要的。

**验证手段**（不要猜）：
```csharp
Logger.Log($"[CharBoss] manager inTree={manager.IsInsideTree()} visible={manager.Visible} pos={manager.Position} " +
           $"children={manager.GetChildCount()} orbContainer={container?.GetChildCount()}");
```

## 5. 环境里的"地雷"（不装这些坑会反复踩）

1. **RitsuLib**（用户装的第三方 mod）会包一层钩子监听者，并逐个调
   `CombatState.Contains(model)`；原版那个方法是 `relicModel.Owner.IsActiveForHooks` 这种**不做空判断**的写法，
   我们的模型只要有一个 `Owner == null` 就链式崩溃 —— 表现是**进战斗直接卡死**（回合起不来、手牌空、能量 0）。
   现在有 `CombatContainsSafePatch`（Finalizer 吞 NRE + 打日志）。日志里会打出是哪个模型的 ID。
2. `PlayerCombatState.MaxEnergy` 会遍历钩子 → 同样会踩上面的雷；日志里读它要 try/catch。
3. `reference sts2.dll` 比游戏旧：`TurnNumber` setter、`RunManager.State` 等都是 internal，
   已有反射封装（`BossHookBridge.TurnField`）。
4. mod 程序集里的 Godot 节点**收不到 `_Process`**（本项目实测）→ 用 `GetTree().ProcessFrame` 事件。
5. PCK 里放贴图要同时放 `x.png` + `x.png.import` + `.godot/imported/*.ctex`（见 `tools/art/pck_extras.txt`），
   否则 `res://x.png` 加载不了。
6. 单文件 ≤200 行是项目硬规矩；超了就拆 partial 分部文件。
7. 用 PowerShell 改 `.gd`/中文文件极易写坏（编码/缩进）；**改文件一律用编辑工具**，不要用 shell 字符串替换。

1. **能量栏闪烁** → `BossStatusRow.Fill` 不再销毁能量球节点（`EnergyCounterNode` 静态缓存，

3. **和球有关的牌卡在空中** → `CardCmd.AutoPlay` 外包 5 秒超时，超时记日志并跳过该牌，
   避免整回合被一张牌的动画/音效 await 拖死。
