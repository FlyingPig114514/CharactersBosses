**本文的三条口径**（都是代码事实，不是我编的约定）：

1. **遗物顺序 = `Relics()` 定义顺序 = 状态栏从右到左**。依据 `UI/BossStatusRow.cs:323 OrderRelics`：
   「起始遗物在最右，涅奥的祝福第二，其余按定义顺序往左铺」——涅奥的祝福若不在下标 1，会被强制挪到下标 1。
   角色自带的起始遗物（铁甲=燃烧之血、亡灵=缚魂命匣、储君=天赋君权…）由 `Player.CreateForNewRun` 建影子玩家时就给了，
   定义里重名的那一条会被 `GetRelicById != null` 跳过 ⇒ 它仍然占**最右**那一格。
2. **回合 N = 她的第 N 个回合**；「打出」按剧本书写顺序（`BossTurn.Cards` 的顺序就是真打出的顺序）；
   「不出」= 剧本造进手牌但本回合打不出/主动留手（`ScriptCard.HoldInstead`，或费用不够由规划器自动跳过）的牌。
   循环按 `BossScript.TurnAt` 的算法（`LoopFrom` 是 **1 起**，`index = LoopFrom-1 + (turn-LoopFrom) % LoopLength`），
   **注释里写的循环区间与实际代码不一致的地方我在下面逐条标出**。
3. 进阶 8/9 采用「变体接管时，主定义该幕的进阶行不生效」的规则
   （`BossDefinition.VariantAscensionUpgrades` / `ShadowPlayerFactory.cs:121`）。

# 控制台指令与血量核对

## 血量规则（代码核实）

`CharBossMonster.MaxInitialHp = Def.HpForAct(ActIndex) + BlessingHpBonus + VariantHpBonus`
（`Monsters/CharBossMonster.Descriptor.cs:94`），进房后 `FixActHp` 再用同一个公式校正一次；`MinInitialHp` 与它相同 ⇒ **没有血线区间，固定值**。

- `BlessingHpBonus = 120 + 180 × ActIndex`（1 起幕号见下；`NeowBlessing.PickupMaxHpBonus = 120`、`PerActMaxHpBonus = 180`）
  ⇒ **第一幕 +120、第二幕 +300、第三幕 +480**。所有 5 个定义都没关 `CarriesNeowBlessing` ⇒ 一律生效。
- `Def.HpForAct(act) = 角色 `CharacterModel.StartingHp` + (Hp[act] − Hp[0])`，而「逐幕加成」**只在主设计生效**：
  变体接管这一幕时按 0 算（`BossDefinition.HpForAct` 的 v0.2.368 说明）。
  ⇒ 唯一吃加成的是第三幕亡灵契约师主设计（根除骨）的 `Hp[2] = 97 = 66 + 31`（布质果实 +31）。
- `VariantHpBonus` 目前只有**事件机**（`DEFECT_EVENT`）写着 `HpBonus = 20`（大蘑菇）。
- 角色基础血量（`docs/plans/cards-*.md` 的「起始生命」+ `BossDefs` 注释）：铁甲 80 / 猎人 70 / 故障 75 / 亡灵 66 / 储君 75。
- **进阶不改变血量**：`AscensionUpgrades*` / `AscensionRelics*` 只发卡牌升级与遗物，没有血量表。

## 与「现有表格」的差异（明确列出）

现有表格写的 **第一幕 220 / 216 / 225 / 230 / 225**、**第三幕 520 / 520 / 525 / 516 / 525**，与上面的规则不一致，原因是它们用的是**旧的涅奥祝福数值 150/幕**（`NeowBlessing` 注释：2026-10-31 之前是「拾起 150、每幕 150」，现在是「拾起 120、每幕 180」）：

1. **第一幕五个值全部偏高 30**：`220/216/225/230/225` 正好等于 `基础 + 150`（猎 70+150=220、骨 66+150=216、机 75+150=225、战 80+150=230、储 75+150=225；列序与一层行动序「猎骨机战储」一致）。现行应为 **200 / 190 / 195 / 186 / 195**。
2. **第三幕四个值 = 基础 + 450（150×3）**：猎 520、机 525、骨 516、储 525 —— 全部对得上旧口径；但「战」那一格写 520 与旧口径的 530（80+450）都对不上 ⇒ **待确认（原始表格的列序/该格数值）**。
3. **顺带三个硬错误（不只是旧数值）**：
   - 第三幕的 **516** = 66 + 450，正是「根除骨漏算布质果实 +31」的旧 bug 值；`HpForAct` 的 v0.2.286 已修 ⇒ 现为 **577**。
   - 第三幕 **520/525** 里没有任何一格考虑了**事件机**的大蘑菇 +20 ⇒ 事件机应为 **575**（与同层能力机/状态机的 555 不同）。
   - 第三幕亡灵契约师有两套设计，血量**不同**：根除骨 **577** vs 养手骨 **546**（变体接管时不吃主设计那 +31）；表里只写一个「骨」的数值必然错一半。
4. 现行第三幕应为：**560 / 550 / 555（能力机、状态机）/ 575（事件机）/ 577（根除骨）/ 546（养手骨）/ 555（无色储君、辉星储）**。

## `fight` 只出 1 只 Boss

`fight <KEY>_BOSS_ENCOUNTER` 走的是我们的**单怪遭遇**：`CharBossEncounterBase.AllPossibleMonsters` 只声明 `Monster<TMonster>()` 一只，
`GenerateMonsters` 里额外追加的「伙伴 Boss」来自 `MultiBossPlan.PartnersForWithKeys`，而它在 `!WantsSecondBoss(out _)`（= 真人玩家数 < 2）时**直接返回空列表**（`MultiBossPlan.cs:126` 「单人：一只都不加」）。
⇒ **单人控制台 `fight` 每场必定只有 1 只 Boss**；只有多人局（≥2 真人）才会按玩家数同时上场多只（此时同一遭遇会出 N 只，N = 真人玩家数，第 4 幕及以后不追加）。
所以上面那张表里的血量只在单人局成立；多人局里每只 Boss 都是同一套公式下的独立个体。
