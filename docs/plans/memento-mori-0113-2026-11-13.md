# 适配 0.113.0（铭记死亡重做）—— v0.2.590，2026-11-13

> 游戏今天更新到 **v0.113.0（commit 16ac0fe3）**，原版重做了「铭记死亡」。
> 本轮把 111 构建整体换到 0.113 的 API，并按新卡牌改剧本 / 多人目标 / 意图 / 特殊效果文案。
> 两个编译目标（107 = 正式版、111 = 当前 beta = 0.113）都是 0 error。

## 0. 原版改了什么（反编译 0.113 的 `MementoMori`）

```csharp
public sealed class MementoMori : CardModel
{
    public override IEnumerable<CardKeyword> CanonicalKeywords => [CardKeyword.Sly];          // 奇巧
    protected override IEnumerable<DynamicVar> CanonicalVars => [new DamageVar(19m, ValueProp.Move)];
    public MementoMori() : base(3, CardType.Attack, CardRarity.Uncommon, TargetType.RandomEnemy) {}  // 3 费
    protected override async Task OnPlay(PlayerChoiceContext ctx, CardPlay cardPlay)
    {
        var hittable = CombatState.HittableEnemies;
        if (hittable.Count != 0)
        {
            Creature target = hittable.MinBy(c => c.CurrentHp);        // 生命值最低
            await DamageCmd.Attack(DynamicVars.Damage.IntValue).FromCard(this, cardPlay)
                .Targeting(target).WithHitFx("vfx/vfx_attack_slash").Execute(ctx);
        }
    }
    protected override void OnUpgrade() => DynamicVars.Damage.UpgradeValueBy(4m);   // 19 → 23
}
```

旧的 `CalculationBase / ExtraDamage /「每弃一张 +4」` 全部消失。

## 1. 0.113 的 API 破坏（编译实测，逐条修掉）

| 破坏 | 现象 | 处理 |
|---|---|---|
| `MultiplayerScalingModel` 换命名空间 | `CS0234 Models.Singleton 不存在` | `BossMultiplayerHpPatch` 加 `#if STS2_107` 类型别名（新版 `Models.MultiplayerScalingModel`） |

| `CardPileCmd.AutoPlayFromDrawPile` 多了一个带 `Action<CardModel>` 的重载 | 运行时 `Ambiguous match for HarmonyMethod` | 属性里写死 5 参数签名 |
| `ActModel.GenerateRooms` 新增 `(RunState)` 重载、旧签名末尾多 `isBlitz` | 同上 Ambiguous | 属性按版本写死参数表（107 三个参数 / 111 四个参数） |
| `ToastyMittens.BeforeHandDraw` 在 0.113 已不存在 | `Patching exception in method null` | `MittensBeforeHandDrawCompat` 整类 `#if STS2_107` |

## 4. 多人：铭记死亡真的打「生命值最少的玩家」

新增 `Patches/MementoMoriLowestHpPatch`（仅 111）：前缀接管 `MementoMori.OnPlay`，**只对我们自己的 Boss 生效**
（玩家/原版怪打这张牌完全不受影响），目标换成新加的
`BossLockOn.LowestHpRealPlayer(combat)` —— **只数活着的真人玩家，忽略奥斯提等召唤物**，
结算仍走原版管线 `DamageCmd.Attack(...).FromCard(...).Targeting(...).WithHitFx(...).Execute(...)`。

意图侧（`BossIntentBuilder`）：`MEMENTO_MORI` 的 `aimedElsewhere` 改由 `MementoMoriAimedElsewhere` 判定
—— **只有「本地玩家就是那只最低血玩家」时才显示伤害意图，其他人显示 0**；
其它牌仍按锁定关系（用户：「其它牌仍以锁定的玩家为目标，别影响其它牌和boss」）。

`BossDamagePredictor.MementoMoriDamage` 在 111 构建里直接读牌面伤害（19/23），不再算弃牌加成。

## 8. 顺带修的一个装机隐患

`install-mod.bat` 里的 `copy /Y ... >nul` 在**游戏开着**时会因文件被占用而**静默失败**，
于是游戏目录里出现「Impl107 新版 + Impl111 旧版」的混版（v0.2.502 的联机不同步就是这个原因，
本次 v0.2.591 又踩了一次：源产物是 0.2.591、部署的 Impl111 还停在 0.2.590）。

新增 `tools/verify-deploy.ps1`（比对两份实现的版本串 vs 清单版本），并在 `install-mod.bat`
拷完两份实现后立刻调用；不一致就打印 `✗ 部署版本不一致` 并提示「关掉游戏重跑」。
实机验证：现在每次装机都会多一行 `[verify] 两份实现的版本串都是 v0.2.591  OK`。

## 9. v0.2.592：阿拉伯数字 + 幻影之刃削弱核对

**① 文案里的中文数字改掉**（用户：「九改成阿拉伯数字9」）：
`BOSS_SUPPRESSION_POWER.description` / `.description_v113` / monsters 的 `SILENT_BOSS.suppression`
三处、zhs + zht 共 6 处「第九回合」→「第9回合」（其余 14 种语言本来就是 `turn 9`）。

**② 0.113.0 把「幻影之刃」削了 1 点**：

| | 0.111 / 107 | 0.113 |
|---|---|---|
| `PowerVar<PhantomBladesPower>` | 9（升级 12） | **8（升级 11）** |
| 升级增量 | +3 | +3 |

核对结论：**我们的意图预览没有写死任何数字**，两条来源都是实时读 ——
· 这层 power 已经挂在她身上 → `PhantomShivs.AmountOf` → `GetPowerAmount<PhantomBladesPower>()`；
· 本回合还没打出（只在她手里）→ `BladesGrowth` 的 `VarInt(card, PhantomBladesPower)` → 牌面 `DynamicVars`。
⇒ 0.113 上刀猎「第一把小刀 +N」的预览会自动少 1 点，**逻辑不需要改**；
顺带确认 `Shiv` 本身仍是 4 点伤害（`ShivBaseDamage = 4` 依旧正确）。
`PhantomShivs.cs` 与 `BladesGrowth.cs` 里那几条写着「9 / 12」的注释已标注成「0.111/107 的旧值」。

**③ 装机自检的两个漏洞（本轮发现并修掉）**：

1. `BuildInfo.Tag` 是一整条串着历史版本的字符串 ⇒ 用「文件里含 vX.Y.Z」判定会命中**旧版本号**，
   混版也能通过。改成**只认文件里第一处** `vX.Y.Z / `（`Read-Utf16FirstVersion`）。
2. 自检原本插在「拷实现之后、拷清单之前」⇒ 它读的是**上一版**的清单版本。
   已挪到清单拷完之后（`[4/4]` 之前），实机确认输出 `[verify] 两份实现的版本串都是 v0.2.592  OK`。
