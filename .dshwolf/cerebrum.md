# Cerebrum

Learned preferences, project conventions, and corrections.

## Preferences

- 打包规则（用户 2026-11-06）：**只有用户明确说「打包」/「上传」时才生成 .dist 里那份 zip**；日常 `install-mod.bat` 不再自动打包（已改成要带 `pack` 参数）。中间版本全是 bug，留着没用，.dist 只保留已发布版本的 zip。
- 回复形态（用户 2026-11-06 指定）：**大段内容一律写进工作区文件**（表格/清单/日志原文/代码摘录），聊天里只回 3~5 行要点 + 文件路径。原因：DSH Web 前端无虚拟滚动，贴大表格/长日志会把这个会话的页面拖到卡死。
- 当用户说「有玩家」「玩家反馈」或发聊天截图时：这是**其它玩家**的 bug 报告，任何一端都不是本机/用户本人；不能要求本机复现，要按「只看玩家日志/截图推断」的方式处理。
- 用户 2026-11-03：「以后做完就直接装游戏」—— 每次 build 完直接把 dll/json/pck 装到 `D:\SteamLibrary\steamapps\common\Slay the Spire 2\mods\CharacterBosses` 与 `D:\SteamLibrary\steamapps\workshop\content\2868840\3830639796\CharacterBosses`（这两条路径在工作区外，需要 danger-full-access），不必再问。
- 打包（Compress-Archive 出 .dist\CharacterBosses-vX.zip）必须等用户明确要求，默认不打包；只构建 + 装进游戏。
## Conventions

- Boss 名与特殊效果名相互独立：「状态机」是 Boss 名，「同步」是它的特殊效果名；特殊效果名一般与某张卡牌同名（例外：死亡收割，是 1 代卡），但效果可与该卡无关。不要用一方推断另一方，等用户明确告知。
- 【皮肤 mod 兼容】皮肤 mod 有三类做法：①改 `CharacterModel.VisualsPath`（或 pck 覆盖同路径资源）；②改 `CharacterModel.CreateVisuals()`；③**在 `NCreature._Ready` 后置补丁里判 `entity.Player?.Character.Id.Entry` 再塞自己的场景**（工坊「空洞骑士」皮肤就是这样）。我们这只 Boss 的影子 Player 是在 `AfterAddedToRoom` 才绑的 ⇒ `_Ready` 那一刻 `Entity.Player == null` ⇒ 第③类一律失效。解决办法：绑好之后用 `Harmony.GetPatchInfo`（反射，这版是 internal）拿到 `Patches.Postfixes`，把别家挂在 `_Ready` 上的、签名是 `static void X(NCreature)` 的后置补丁对我们这只 Boss 的节点**补跑一次**（每只只补一次，那些补丁不幂等）。
- 【本沙箱启动游戏】`Start-Process "steam://run/2868840"` 起不动，但 **`cmd.exe /c start "" "steam://run/2868840"` 可以**（实测 2026-11-04，Steam 已运行）。另外游戏进程被强杀后重新启动会**自动续上存档**（直接进到战斗里），所以实机复现不用每次从头打。
- 【为你而死 / 奥斯提挡伤的唯一判据】`DieForYouPower.ModifyUnblockedDamageTarget`：`if (!props.IsPoweredAttack()) return target;`，而 `IsPoweredAttack(props) = HasFlag(Move) && !HasFlag(Unpowered)`。⇒ 一切「无来源」伤害（`ValueProp.Unpowered`）奥斯提都不挡：黑洞、群蛇形态 4、充能球被动、炸弹、冰雹风暴、卡戎之灰。另外反编译确认：格挡取自 `originalTarget.PetOwner?.Creature ?? originalTarget`（打宠物时格挡算主人的），改派发生在扣完格挡之后，`DamageResult` 是拿**改派后的目标**建的 ⇒ 宠物替死也算一次「击杀」。
- 【实机测试技巧】要复现「玩家手里恰好有某张牌」的场景（如吹哨击晕、连晕两回合）不要靠抽牌运气：①在 mod 目录放 `charbosses_debug.txt`（第一场普通战斗变成角色 Boss，见 Core/DebugMode.cs）；②临时加一个自检类，读 mod 目录里的开关文件（写回合号），在玩家回合开始 1.2 秒后直接调 `CreatureCmd.Stun` 等入口，验完**删掉并重 build**。另外实测发现玩家卡组里本来就带 WHISTLE（吹哨），自动打牌时它自己也会反复击晕 Boss。读 mod_log.txt 必须用 `Get-Content -Encoding UTF8`，否则中文全变乱码、grep 中文模式永远搜不到。
- 【击晕/STUNNED】`Creature.IsStunned => Monster?.NextMove.Id == "STUNNED"`（NextMove 只由 `MonsterModel.RollMove` 赋值）；`CreatureCmd.Stun` 传的 stunMove 是**空 Task**，真正起作用的是把移动状态机切到 STUNNED（`MustPerformOnceBeforeTransitioning=true` ⇒ 晕着的时候 RollMove 第一行就 return，不推进状态机）。我们这只 Boss 因此**天生**做到了「本回合不行动」（PerformMove 跑空 Task ⇒ PlayPlannedCards 进不去 ⇒ Plan/TurnNumber/手牌原封不动）。要让「下回合补打被打断的那一套」，只需在 `CharBossMonster.PrepareTurn()` 开头（Plan.Clear() 之前）加 `if (Stunned) return;` —— 别去接管 CreatureCmd.Stun，也别手改 NextMove。
- 中文简称「贼 → 猎」（2026-11-03 用户要求）：刀贼→刀猎（SILENT_SHIV 刀贼/小刀轴）、奇巧贼→奇巧猎（SILENT_SLY）、涂毒贼→涂毒猎（SILENT_ENVENOM）、炼药贼→炼药猎（SILENT_BREWER）、蛇眼猎（SILENT_SNECKO）。用户以后仍可能口语说「贼」——那他指的是同一批静默猎手变体 Boss（刀/奇巧/涂毒/炼药）。
- 文案口径（用户 2026-10-29 明确）：特殊效果描述里的「你 / you」= **被这只 Boss 跟踪锁定的那位玩家**（单体/对应型），不是「任何玩家」。由 `BossLockOn.SpecialEffectAppliesTo` 把关的效果，英文禁止写 “a player / all players”；确实是全队收益的（例如彗星的格挡/清负面）才写 all players。
- 地图 Boss 徽章的贴图路径 = `NBossMapPoint._Ready` 里的 `enc.BossNodePath + ".png"` / `+"_outline.png"`（不是 `ImageHelper.GetRoomIconPath`，那是结算/顶栏用的）。基类兜底到 `TheKinBoss.BossNodePath` 会把「披甲武士」画在我们的遭遇上 ⇒ 出现「提示写 A、图标是 B」的错配；没有专属美术的档位应改用 `CharacterModel.IconTexture` 的白色剪影（白色才能被 `ActModel.MapTraveledColor` / `MapBgColor` 染色成原版观感）。
- 本模组的本地化/美术都在 PCK 里（`content/` → `res://CharacterBosses/...`）：**只改 DLL 时复制 DLL+清单即可；一旦改了 `content/` 或 `tools/art/pck_extras.txt` 就必须重打 PCK**（`tools\godot\Godot_v4.5.1-stable_mono_win64_console.exe --headless --path tools\pck_builder --script build_pck.gd -- <清单绝对路径> <输出pck绝对路径> <content绝对路径> CharacterBosses <extras绝对路径>`），否则新键/新图一个都不会生效。⚠ 输出路径必须绝对——Godot 把相对路径解析到 `--path` 的项目目录，否则报 `Failed to start PCK packer: 20`。可用 `find_in_pck.gd` 在包内搜字符串自检。
- StS2 状态栏 Power 图标的真实实现是 `NPowerContainer`（不是 NPowerIcon，那个类型不存在）：`_powerNodes` 是 `List<NPower>`，`Add` 由 `Creature.PowerApplied` 触发且**不去重**，`Remove` 由 `PowerRemoved` 触发但 `CombatManager.Instance.IsInProgress == false` 时**整段跳过**、且按引用只摘第一个匹配项；`PowerModel.IsVisible` 里有 `LocalContext.IsMe(Target)` ⇒ 联机时队友身上的 Power 要不要显示归原版本地判定。凡「图标多一个/摘不掉」优先查这三处。
- BaseLib 配置界面里**别**用 `NTickbox` / `NConfigTickbox` / `NConfigOptionRow`：前两个裸 new 出来没有视觉子节点（勾选框的图来自 `res://scenes/ui/tickbox.tscn`），而且子类 `_Ready` 里**不能**调 `base._Ready()`（原版直接抛 `Don't call base._Ready()! Call ConnectSignals() instead.`）；后者把控件排到行尾，当前窗口尺寸下控件落到屏幕外。可行方案（v0.2.122 实测通过）：自己搭 `HBoxContainer` 行（**控件在左、文字 ExpandFill**），勾选框 = 普通 `Button`（`Flat`+`ToggleMode`）切换游戏自己的贴图 `res://images/atlases/ui_atlas.sprites/checkbox_ticked.tres` / `checkbox_unticked.tres`。另外 `ModConfig.CreateRawLabelControl` 造的 `MegaRichTextLabel` **高度 0、最小宽度 1**，必须给 `CustomMinimumSize(0,64)`+ExpandFill（说明性小字用 `FitContent=true`），否则整行什么都不画。
- BaseLib 的配置界面用法（模组配置子菜单）：写一个 `SimpleModConfig` 子类（**必须放在命名空间里**，BaseLib 用根命名空间给 .cfg 定名，且只有无参构造），override `SetupConfigUI(Control)` 往容器里塞行；控件工厂 `CreateRawButtonControl(text, action)` / `CreateRawTickboxControl(prop)` / `CreateRawDropdownControl(prop)`，标签用静态 `ModConfig.CreateRawLabelControl(text, 24|28|40)`，分隔线 `CreateDividerControl()`，标题 `CreateSectionHeader()`；没有配置属性时**必须** override `VisibleInModList() => true`，否则不会出现在列表里；注册用 `ModConfigRegistry.Register(modId, instance)`（自己调，别指望自动发现），挂 `NMainMenu._Ready` 后缀（挂 `NGame._Ready` 不触发：补丁生效时那次已经在跑了）。
- **二代 Boss 音乐的 `<boss>_progress` 参数是死路**（本模组实测）：`insatiable_progress` 用 `UpdateMusicParameter`（事件内）或反射 `_proxy` 调 `update_global_parameter`（全局）都返回成功、**音乐毫无变化**；唯一有效的是 `PlayCustomMusic` 换曲目（换成知识恶魔立刻听得出）。`STS2_*_Layer1~5` 是同一事件内部的层，原版也只在死亡时写一次 10。⇒ 想做「随血量变激昂」只能换曲目，别指望参数。
- 二代 Boss 音乐（FMOD）不需要挖 bank：原版每个 Boss 遭遇都覆盖 `EncounterModel.CustomBgm` 返回完整事件名（如 event:/music/act1_boss_the_kin），`CombatManager` 战斗开始时若 `HasBgm` 就 `PlayCustomMusic(CustomBgm)`；分段/重音走 `NRunMusicController.UpdateMusicParameter(\"<boss>_progress\", 值)`。曲目只在当前幕的 bank 里，跨幕播=整场没音乐。
- StS2 伤害倍率：虚弱(WeakPower)=0.75，但若攻击者身上有摧残(DebilitatePower，卡 Debilitate 施加，2 回合)则变 0.75→0.5（实现 amount-(1-amount)）；纸鹤(PaperKrane) 再 -0.15。所以「吃虚弱后伤害减半」通常是 虚弱+摧残，不是虚弱算两遍。
- 所有角色 Boss 的遗物顺序：第 1 件 = 自己角色的起始遗物，第 2 件 = 涅奥的祝福（NeowBlessing）。必须显式写进该 Boss 的 Relics() 第 2 位；靠 ShadowPlayerFactory 自动追加会排到末尾（状态栏顺序错）。涅奥的祝福的图标用「涅奥的牺牲」neows_sacrifice（不是 neows_talisman）。
- 构建指纹 BuildInfo.Tag 是「每次改 DLL 就 +0.0.1」的单调计数器，不是语义化版本：永不跳段、永不重编号；同时必须同步 src/CharacterBosses.json 的 version（会打进 PCK 的 mod_manifest.json）。当前线：v0.2.12（历史误标：0.1.98→0.2.0、0.2.9→0.3.0 两次跳段）。
- 要让「群体减力量」类效果绕开 Boss 随从（奥斯提）：切 `PowerCmd.Apply(ctx, PowerModel power, Creature target, decimal amount, Creature applier, CardModel, bool silent)` 这个**非泛型**重载（泛型 Apply<T> 最终都走它），判 `power is TemporaryStrengthPower`（尖啸 PiercingWailPower / 黑暗镣铐 DarkShacklesPower 都继承它）或 `StrengthPower && amount<0`，目标 `creature.PetOwner?.Creature?.Monster is CharBossMonster`，施加者是真人时跳过；返回 false 时必须 `__result = Task.CompletedTask`。
- 「剧本里会加力量的牌」（烙印 Brand：PowerVar<StrengthPower>(1) ⇒ DynamicVar key = Strength）在规划期不存在于她身上 ⇒ 它之后那些攻击的预览要按「逐张累计 plannedStrength − PlannedStrengthGainedThisTurn」提前补，牌结算完再撤回。同一个 DynamicVar key 规则也用于吞噬生命（DevourLife）。
- Boss 遗物的「战斗内事件」钩子（RelicModel.AfterCardExhausted 卡戎之灰 / BeforeSideTurnEnd 奥利哈钢）对影子玩家不派发（遗物只从 CombatState.Players 取）。需要时用 BossDefinition.FireBossRelicHooks 开关 + Patches/BossRelicHookBridge 手动补跑：消耗钩子挂在 Hook.AfterCardExhausted 的 postfix；回合结束钩子在 CharBossMonster.PlayPlannedCards 末尾（丢手牌之前）调 BeforeSideTurnEndVeryEarly/BeforeSideTurnEnd。
- 跨 Boss 影响自查顺序：每次给「灵魂骨」加机制后，逐个检查是否有全局路径（BossScriptPlanner/BladesGrowth/CharBossMonster.PlayOne/PlayPlannedCards 都不区分 Boss）——需要按 Boss 区分的行为一律用 `Creature.GetPower<BossSoulBoundPower>() != null` 加闸门，因为那个能力只有二层灵魂骨有。
- 奥斯提生命来源（反编译）：①召唤牌取 `Summon` 变量；`OstyCmd.Summon` 已有奥斯提走 `CreatureCmd.GainMaxHp(osty, amount)`，没有则 `SetMaxHp+Heal`。②`DevourLifePower.AfterCardPlayed`：打出 `Soul` 且 owner 匹配 → `OstyCmd.Summon(owner, power.Amount)`。「出击 Unleash」伤害 = CalculationBase + ExtraDamage × 奥斯提当前生命，所以预览要提前加这两类。
- 原版「回合开始补手牌」= CombatManager.SetupPlayerTurn 里的 CardPileCmd.Draw(..., fromHandDraw: true)；所以 fromHandDraw 能用来区分「回合开始抽牌」和「回合内额外抽牌」（用户口径：前者不算死亡行军/自动化）。
- 要「写死某张剧本牌的伤害」时用 ScriptCard.DamageOverride（BossScriptRunner.BuildHand 里改这一张实例的 DynamicVars.Damage.BaseValue）；PlayerCombatState.RecalculateCardValues 只重算附魔，不会覆盖它，所以意图和实战都会跟着变。
- 卡牌数据：Automation（自动化）基础 1 费，OnUpgrade = EnergyCost.UpgradeBy(-1) ⇒ 自动化+ 是 0 费；Dirge（挽歌）HasEnergyCostX=true（X=打出时的剩余能量，召唤 X 次 3 点 + X 张灵魂进抽牌堆）；Delay（拖延）基础 2 费、升级只加格挡/给下回合能量的数值，不改费。

## Do-Not-Repeat

- 【Do-Not-Repeat】本仓库 `tools\*.ps1` 里凡是**含中文**的脚本，必须存成 **UTF-8 带 BOM**。Windows PowerShell 5.1 会把无 BOM 的 .ps1 当 ANSI(GBK) 解码 ⇒ 中文字符串被拆成乱码字节、吞掉引号/花括号，报一堆假的语法错（`Missing expression after ','`、`Unexpected token ')'`）。2026-11-04 `tools\feishu-stats.ps1` 就是这么坏的（其余中文脚本都有 BOM，只有它没有）。检查：`[System.IO.File]::ReadAllBytes($p)` 头三字节是否为 EF BB BF；修法：`[System.IO.File]::ReadAllText($p, UTF8)` 再 `WriteAllText($p, $text, New-Object System.Text.UTF8Encoding($true))`。用 write 工具新建/重写含中文的 .ps1 后，务必补一次 BOM。
- 【Do-Not-Repeat】不要用 `Start-Process SlayTheSpire2.exe` 直接启动游戏（用户 2026-11-04 指出会被 Steam 拦下来）。用 `powershell -ExecutionPolicy Bypass -File tools\launch_sts2.ps1`（内部 steam://run/2868840）；本沙箱里 steam:// 协议可能起不动，那就让用户自己启动。关游戏用 `Stop-Process -Name SlayTheSpire2 -Force`（tools\close_sts2.ps1 里的 tskill 在新 Windows 上不存在）。
- 【Do-Not-Repeat】Harmony Prefix 跳过**返回 Task 的方法**时，必须 `ref Task __result` 并赋 `Task.CompletedTask`；少这一句 Prefix 就会让方法返回 null（default(Task)），下游 `.GetAwaiter()` 直接 NRE，把整条钩子链炸掉。症状会伪装成完全无关的 UI 问题（StS2 里就是「结束回合按钮消失 + 回合结束管线不跑 + Boss 一手不出」）。新增/修改任何 return false 的 Prefix 前，先用 ilspy-cli 确认目标方法返回类型：返回 Task 的一律要 __result。已踩过两次：EmotionChipBossTakeoverPatch（v0.2.356 修，事件机不可玩的真凶）、ConfusedPowerBossPatch（v0.2.356 顺手修，蛇眼猎抽牌必炸）。
- 事件机「没有结束回合按钮」未修好（2026-11-04 交接）。已排除：选择悖论弹选牌、她的出牌流程、一心化万的异步链、羽化预览、无礼之茶。关键实证：探针显示按钮前置条件全满足但 `NEndTurnButton._state == Hidden`；且 `Hook.AfterPlayerTurnStart` 抛 NullReferenceException（2ms）打断玩家回合开始流程。v0.2.355 的 finalizer 没生效（`PlayerTurnStartHookSafetyPatch.CombatHasOurBoss` 只查 Allies/Enemies 判断失败）；「强制打开按钮」也被 `AllPlayersReadyToEndTurn()==true` 挡住。强烈怀疑 `RoyalPoison.AfterPlayerTurnStart`（读 Owner.PlayerCombatState 可能 NRE）。完整交接见 docs/plans/handover-2026-11-04.md。
- 编辑带 BOM 的 .ps1（tools/feishu-*.ps1）后必须重新写回 BOM：edit/write 工具会写成无 BOM 的 UTF-8，PowerShell 5.1 会把中文当 ANSI 读成乱码并报「字符串缺少终止符」类语法错。改完用 [System.IO.File]::WriteAllText(路径,文本,New-Object System.Text.UTF8Encoding($true)) 补 BOM，再用 Parser::ParseFile 校验。
- 不要在代码注释里把「用户说过某句话」当成事实依据：本轮就是因为一条我自己写的「用户 2026-10-29：亡灵契约师统一用群魂/骷髅」注释，把 soul_bone 一刀切给了三个档位，用户否认后白改两版。涉及「用户要求」的注释必须写清依据（原话 / 日志行 / 截图），没有依据就标「待确认」。
- 【Do-Not-Repeat】HarmonyPatch 用 nameof 时必须写死参数类型（第三参 new Type[0] / new[]{typeof(X)}）：只要有重载（例如 NRunMusicController 有两个 UpdateTrack），Harmony 抛 AmbiguousMatchException → PatchAll 中断 → 整个模组所有补丁都没挂上，游戏弹「模组程序集DLL初始化失败」。新增补丁前先用 ilspy-cli members 数一下同名方法个数。
- 绝不用 PowerShell 的 `Get-Content`/`Set-Content` 改**含中文的文件**：本机 PS 5.1 的 `Get-Content -Raw` 按 ANSI(GBK) 解码 UTF-8，`Set-Content -Encoding UTF8` 再写回 ⇒ 整个文件变乱码（2026-10-29 把 `.dshwolf/STATUS.md` 写坏了一次）。只用 `read`/`write`/`edit` 文件工具，或 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`。
- 绝不给我们自己的 UI 节点抬 `ZIndex`（面板/意图行/状态条都一样）：抬起来之后切到**地图、设置、图鉴**时，本模组的卡面/意图会浮在那些界面之上（2026-10-29 连试 200 / 10 / 「意图行挂面板下 + ZIndex=2」三种方案全部失败）。`BossStatusRow.Icons.cs` 里早就记过同一条教训。Godot 的 `CanvasItem.ZIndex` 只在**同一父节点**的兄弟之间比较，「让它压过卡牌」不能靠抬整块面板。
- `src/Hooks/Core/BossOsty.cs` 的注释已经被过去某次 PowerShell 字符串替换毁成乱码（210 处 U+FFFD，「�?」到处可见）——**只伤注释、没伤字符串字面量与代码**（2026-10-29 核对过），所以别以为文件坏了就重写它；要修只做「整文件按 UTF-8 重写注释」，并且绝不要再用 PowerShell 替换去改 .cs。
- 多人局里「我们自己的 PowerModel」不跨客户端同步，而且会被游戏的生命周期摘掉；想给玩家看的提示不要靠 Power 图标，画在自己的 UI 上。
- 多人局里任何「全局开关 + 作用域开关（Push/Pop）」改原版选靶的写法都会串到别人的结算上（播种只打一人那次）——改成「一次性 + 帧窗口」的 request/consume，并在出牌前清残留。
- 本模组自绘 UI 时不要用 CheckButton/CheckBox（游戏主题没图标 ⇒ 完全看不见），也不要依赖自己的 Godot 回调（_Process / ProcessFrame / Control.Resized 信号实测都不触发）；交互一律走「挂在原版方法上的 Harmony + 文字状态」，自检用 F9 类热键 + SendKeys 驱动（键盘这条路是通的）。
- StS2 伤害取整是**向下取整**，不是四舍五入：AttackIntent.GetSingleDamage 用 (int)num，Creature.LoseHpInternal 用 (int)Math.Clamp(amount,0,…)。我们自己的预览计算一律用 (int)Math.Floor（BossDamagePredictor.FloorToInt），别用 Math.Round，否则 .5 时比原版多 1 点。
- 炼药贼（SilentBrewerScript）第 2、第 7 回合与初始 8 瓶药水里那一瓶是「爆炸药水」= 游戏正式名「爆炸安瓿」= ExplosiveAmpoule（对所有敌人=对所有玩家造成伤害），不是火焰药水 FirePotion。用户强调过多次，别再改。
- 本模组里**新增任何 AbstractModel 派生类（Power/Card/Relic/Encounter/Monster）前，先用 ilspycli types 查原版有没有同名类型**：模型 ID 是按类名 Slugify 算的，撞名会让 ModelDb 初始化抛 DuplicateModelException，整个游戏起不来（2026-10-27 的 CoolantPower 就踩了，原版已有 POWER.COOLANT_POWER）。同类已用命名前缀规避：BossSoulBoundPower / BossCoolantPower / BrewModPower / CometBossPower。
